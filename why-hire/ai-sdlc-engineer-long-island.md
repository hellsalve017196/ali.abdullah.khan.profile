## TL;DR

Most teams have bought AI coding tools and got **faster typing**. Typing was never the bottleneck. **Ali Abdullah Khan** built a team workflow that moves the leverage upstream . **JIRA intake → PRD generation → task decomposition → grounded code delivery → automated test coverage** . with GitHub Copilot as the interface and a maintained knowledge base as the source of truth. He is based in **Holbrook, New York**, on Long Island.

## The thesis

> **The knowledge base is the product. The AI is just the interface.**

Output quality is a function of the context the model is handed, and **context is an artifact you maintain** . not a sentence you craft. Two operating rules follow:

1. **If it isn't in the knowledge base, it doesn't exist.** A decision living only in a Slack thread cannot be grounded against, so it gets re-invented differently by someone who was not in the thread.
2. **Start with the 20% of context that answers 80% of the questions.** Trying to document everything first is how knowledge-base projects die half-written and distrusted.

Full post: [How I Built an AI-Driven SDLC with GitHub Copilot and Obsidian](../writing/ai-driven-sdlc-with-github-copilot-and-obsidian.md) · System page: [AI-driven SDLC](../systems/ai-driven-sdlc.md).

## What he would set up for your team

- A knowledge base scoped to the decisions people keep re-asking . not a documentation project
- A **PRD step** between ticket and implementation, reviewed by a human **before** decomposition
- Task decomposition into independently testable units
- Grounded delivery, so the model reads your context instead of inventing a plausible one
- Tests generated **against the PRD**, not against the diff

## The honest limits

It carries a **well-understood requirement** to shipped code. It does not decide whether the requirement is right, and it degrades as the knowledge base goes stale. **Maintaining the vault is the job.** Anyone promising otherwise is selling a tool, not a workflow.
